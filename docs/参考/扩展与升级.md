# TierListBase 平台能力变更规则

> 状态：CURRENT ENGINEERING REFERENCE
> 最近同步：2026-10-23

本文件不再描述“从 creat-web 模板拉更新”。TierListBase 已是独立生产仓库。

它只约束对现有 dormant/shared platform 能力的重大变更。

## 1. 原则

任何 auth、commerce、credits、provider、database、deployment 等平台级能力变更，都必须：

- 先确认当前产品是否真的需要；
- 在独立任务中改变，不与无关产品功能捆绑；
- 明确 migration / env / provider / rollback 影响；
- 保持现有产品配置不被模板式覆盖；
- 通过对应 verifier、tests 和 production checklist。

## 2. Provider 替换或新增

不要复制第二套支付、身份或存储领域模型。

先定义 provider-neutral 边界，再把新 provider 映射到已有领域事实与幂等规则。

对于 commerce，当前 Waffo adapter 仍由 [Waffo 合约与验收](waffo-合约与验收.md) 约束；production commerce 当前关闭。

## 3. 数据库

新增 migration 必须用 Drizzle 生成并通过 `db:verify`。破坏性变更需要显式 expand/migrate/contract 或向前修复策略。

## 4. 部署架构

当前 production 是 GitHub Actions -> Vinext -> Cloudflare。切换部署平台属于架构变更，必须单独设计并同时更新：

- CI
- runtime env
- rollback
- scheduled work
- health checks
- production runbooks

不要因为旧文档曾使用 Vercel 就恢复旧部署路径。

## 5. 完成定义

平台能力变更只有在代码、配置、tests、CI、当前文档和真实 provider/deploy 事实同时一致时才算完成。
