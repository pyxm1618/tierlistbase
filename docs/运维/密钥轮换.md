# TierListBase 密钥轮换

> 状态：CURRENT OPERATING PROCEDURE  
> 最近同步：2026-10-23

通用顺序：

1. 创建新凭据。
2. Provider 支持时建立安全重叠期。
3. 更新批准的 production secret store。
4. 部署并验证对应链路。
5. 吊销旧凭据。
6. 再验证旧凭据失效、新链路正常。

只记录用途、标识、时间和验证结果，不记录 secret value。

## Better Auth

轮换 `BETTER_AUTH_SECRET` 可能影响现有 session。没有明确 multi-key 支持时按会要求用户重新认证处理。疑似泄露时不要 rollback 到旧 secret。

## Google OAuth

轮换 client secret 时保持 authorized origins / redirect URI 不变。先验证新登录和回调，再吊销未泄露的旧 secret。

## Resend

创建受限新 API key，验证真实事务邮件链路后再吊销旧 key。

## Cloudflare deploy

轮换 GitHub Actions 使用的 Cloudflare token/account credential 后，通过受控 CI build/deploy 验证权限。不要给 deploy token 超出所需范围的权限。

## Vanguard R2

轮换 R2 credentials 后验证：

- presign
- private upload
- moderation read
- approved publish
- revoke/delete

private/public bucket 不得在切换时指向同一 bucket。

## Vanguard Workers AI

轮换 `VANGUARD_WORKERS_AI_TOKEN` 后验证 server-side moderation request；token 不进入客户端。

## Database

按 Neon/PostgreSQL provider 支持的方式轮换。新连接验证 health/read/write 后再撤销旧凭据，并确认连接池/worker 已使用新值。

## 事故状态

一旦凭据疑似泄露，优先 containment + rotation。不要为了恢复服务重新启用已经泄露的旧值。
