# TierListBase 生产运维 Runbook

> 状态：CURRENT OPERATING RUNBOOK  
> 最近同步：2026-10-23

本文件是当前 TierListBase 唯一通用生产运维说明。只记录今天实际采用的部署、服务商、恢复和密钥处理方式。

## 1. 当前生产架构

- Source of truth branch: `main`
- CI/CD: GitHub Actions
- Build: Vinext / Vite
- Hosting/runtime: Cloudflare Workers
- Static assets: Cloudflare
- Database: PostgreSQL / Neon
- Auth: Better Auth + Google OAuth
- Transactional email: Resend
- Vanguard private/public media: Cloudflare R2
- Vanguard image moderation: Cloudflare Workers AI
- Analytics: GA4 / Clarity，仅在 consent 允许后加载

当前生产部署不是 Vercel。

## 2. 正常发布

`.github/workflows/ci.yml` 中的 Production Deploy 只在 push 到 `main` 时执行。

部署流程：

1. 完成质量/测试 gate；
2. build Vinext；
3. deploy job 重新获取 remote `main`；
4. 如果当前 workflow SHA 已经不是最新 `main`，拒绝 stale deploy；
5. 使用 Cloudflare production credentials 执行 `bun run deploy:vinext`。

不要为了跳过 CI 手工发布一个旧 commit。

## 3. 上线前检查

涉及生产变更时，按改动范围检查：

### 应用

- `bun run lint`
- `bun run typecheck`
- relevant unit/integration/browser tests
- `bun run build`
- 需要 Cloudflare runtime 时额外 `bun run build:vinext`

### 数据库

- migration 必须由 Drizzle 正常生成；
- `bun run db:verify`；
- 不使用 schema push；
- integration test 只能指向 disposable `TEST_DATABASE_URL`。

### SEO / public pages

- canonical origin 仍为 `https://www.tierlistbase.com`
- robots / sitemap / indexability 与 route registry 一致
- 不把 staging/test URL 作为 production canonical

### Vanguard

需要按变更核对：

- Google OAuth
- R2 private/public bucket 分离
- R2 CORS
- pending 24h lifecycle
- Workers AI moderation
- Resend report notification
- account deletion/media revoke
- 64,128 Seat layout

## 4. 外部配置文件

当前仓库保留两份 Vanguard R2 source config：

- `docs/wow-forever-vanguard/implementation/r2/cors.production.json`
- `docs/wow-forever-vanguard/implementation/r2/lifecycle.private.json`

它们是期望配置，不自动证明 Cloudflare 侧已经应用。变更后需要在目标环境 read-back。

不得把 private bucket 暴露为 public custom domain。

## 5. 密钥轮换

通用顺序：

1. 创建新凭据；
2. 如果 provider 支持，建立安全重叠期；
3. 更新 production secret/config；
4. 部署；
5. 验证对应链路；
6. 吊销旧凭据；
7. 再验证旧凭据已经失效。

记录用途和执行结果，不记录 secret value。

### Better Auth

轮换 `BETTER_AUTH_SECRET` 可能影响现有 session。没有明确 multi-key 支持时，按可能要求用户重新认证处理。

### Google OAuth

轮换 client secret 时不要误改 authorized origins / redirect URI。新 secret 验证成功后再吊销旧 secret。

### Resend

新 API key 先验证事务邮件链路，再吊销旧 key。

### Cloudflare deploy credentials

轮换 production deploy token/account credential 后，通过受控 CI 部署验证权限足够且没有过度授权。

### Vanguard R2

分别轮换 access key/secret，并验证：

- presign
- private upload
- moderation read
- approved publish
- revoke/delete

不要让 private/public bucket 在轮换时被错误指向同一个 bucket。

### Workers AI

轮换 token 后验证真实 server-side moderation request。Token 不进入客户端。

### Database

使用 Neon/数据库服务商支持的 credential rotation。切换前确认连接池和部署环境将读取新凭据；切换后验证 health/read/write，再吊销旧凭据。

遇到疑似泄露，不要为了方便 rollback 恢复到泄露的旧密钥。

## 6. 事故处理

优先顺序：

1. 限制继续扩大影响；
2. 明确受影响版本/服务；
3. 判断是代码、配置、数据库、凭据还是 provider 故障；
4. 必要时暂停会继续写入或扩大事故的路径；
5. 恢复到最后一个**与当前 schema 兼容且安全**的应用版本，或向前修复；
6. 验证关键业务链路；
7. 再恢复正常流量/任务。

不要把“回滚代码”误认为可以回滚数据库历史。

## 7. 代码回滚

合法回滚目标必须满足：

- 与当前数据库 schema 兼容；
- 不重新启用已泄露凭据；
- 不恢复已经废弃的 provider/deploy 结构；
- 能通过最小 production smoke。

至少检查：

- `/api/health/live`
- `/api/health/ready`
- 首页
- WoW/Genshin 代表页面
- Google 登录（涉及 auth 时）
- Vanguard（涉及 Vanguard 时）

## 8. 数据库备份与恢复

不要对 production 做临时 down migration。

需要恢复时：

1. 使用 Neon/托管 PostgreSQL 的 PITR 或批准备份恢复到**新的隔离数据库**；
2. 禁止该恢复库被 production worker/webhook 使用；
3. 运行：
   ```bash
   RESTORED_DATABASE_URL="..." bun scripts/verify-restored-database.ts
   ```
4. 核对 migration history 和业务不变量；
5. 明确恢复点之后已经发生的外部副作用如何重放/对账；
6. 验证通过并经授权后才切换流量。

临时 dump/恢复库按批准策略清理，不提交仓库。

## 9. 死信/后台任务

如果使用现有 dead-letter 运维脚本：

- 先确认根因已解决；
- 只重试确实仍处于 dead-letter 的条目；
- 依赖现有幂等键/事务边界；
- 给出可审计 reason；
- 不直接修改业务结果表“制造成功”。

重复失败表示问题仍未解决，不要无限强制重试。

## 10. 生产 smoke

发布或事故恢复后，按改动范围验证：

- health
- public route
- auth
- database read
- affected write path
- Vanguard manifest/search/claim/media（如相关）
- analytics consent（如相关）
- SEO canonical/robots（如相关）

只有当前受影响链路真实恢复后才关闭事故。

## 11. 不再使用的旧运维模型

以下不是当前 TierListBase production 事实，不应按旧文档恢复：

- Vercel production deployment
- Vercel cron 作为当前任务调度事实
- neutral starter “all features off”
- production Magic Link / Turnstile login flow
- Waffo commerce operations

未来若产品重新启用其中任何能力，应作为独立设计/上线任务重新建立当前文档，而不是复活旧历史说明。
